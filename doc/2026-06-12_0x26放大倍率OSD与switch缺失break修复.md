# 0x26 放大倍率 OSD 显示与 switch 缺失 break 修复

## 问题背景

**需求：** 上位机 0x26 命令协议扩展——原有 Byte2（传感器ID）、Byte3~4（视场角，÷100 显示为 xx.xx）之后新增 Byte5~6（放大倍率，÷10 显示，后缀 x，如 12.5x）。OSD 上原来由 0x17 `sensor_view_size` 驱动的"大/中/小/超/X2"视场标识（槽位字符格 [18][19]）改为显示该放大倍率。

**附带发现：** 拉取 gitlab 提交 `1f73f42`（焦距值索引设置为22，增强增加'透'）时审查 diff，发现新增的 `case '4':`（"透"字）插在 `case '3':` 代码块与 `break;` 之间，`case '3'` 自身没有 break——典型的 **switch fall-through** 缺陷：增强等级为 '3' 时，[14][15] 先写入"中"又立刻被 '4' 分支覆盖成"透"，'3' 永远显示错误。

## 原因分析

### fall-through

C/C++ 的 case 标签不构成作用域边界，没有 break 就顺序执行下一个 case 的语句。这类缺陷编译期不报错（除非开 `-Wimplicit-fallthrough`），运行时只在命中该 case 时才暴露，靠人工 review diff 才提前发现。

### 放大倍率的字符格布局

该 OSD 槽位（`osd_sensor_viewangle_enhance_viewstate_bricont_ir`，32 格）原布局：

| 格 | 内容 | 来源 |
|----|------|------|
| [0]~[3] | 电视/红外/光斑 | 0x02 channel_disp |
| [5]~[10] | 视场角 xx.xx | 0x26 Byte3~4 |
| [14][15] | 增强等级（轻/中/.../透） | 0x21 |
| [18][19] | 大/中/小/超/X2 | 0x17 sensor_view_size |
| [22]~[25] | 手动/自动 | 0x21 |
| [28]~[31] | 黑热/白热 | 0x19 ir_pola |

放大倍率最长 "12.5X" 占 5 格，[18][19] 两格放不下。与甲方确认后采用**往后顺延**：倍率占 [18]~[22]，手动/自动顺延到 [24]~[27]（[23] 留空隔开）。代价是 [27] 与 [28] 起的黑热/白热之间不再有空格，槽位自 [18] 起无空闲格。

### 刷新触发条件为什么必须改

该槽位的重绘由一个大 if 把守（轮询各状态与静态镜像变量比较，变了才重写 32 格并 `update_OSD_chinese` 推 BRAM）。[18]~[22] 的写入在 if 块内部，若触发条件不加 `magnification_str` 比较，倍率单独变化时不会进块，屏上残留旧值，要等视场角等其他状态恰好变化才被"捎带"刷新。虽然倍率与视场角同来自 0x26，但不能假设两者必然同步变（视场角到极限而数字变倍继续、两位小数舍入后字符串不变等场景），不能靠隐含耦合省一个字符串比较。

加 OR 条件的安全性核查：块内全部操作是"按当前状态重算字符数组+整体写 BRAM"，幂等；唯一对外副作用（ir_pola 变化时向 XJ3 发 0x9F）有独立内层 if 把守，多进块不会误发。

## 解决方案

### 实现

- `device.h`：`HostUARTDevice` 新增 `std::string magnification_str`
- `device.cpp` 0x26 分支：视场角之后解析 Byte5~6（int16 小端），`format("%.1lfX", v * 0.1)` 后 `pad_str(5, -1)` 左对齐补空格；以 `param_count >= 5` 做协议兼容保护，旧长度报文不越界解析。构造函数初始化为 5 空格
- `main.cpp`：
  - `case '3'` 块后补 `break;`
  - `sensor_view_size` 的 switch 整块注释（变量赋值保留，触发条件仍引用）
  - [18]~[22] 写 `magnification_str`，[23] 写空格；手动/自动两个 case 的索引 [22]~[25] → [24]~[27]
  - 触发条件追加 `magnification_str.compare(...) != 0`，静态镜像初值 `"---"` 保证首帧必刷

### 权衡

- 顺延而非压缩倍率精度：保住 "xx.x" 一位小数的协议显示要求，牺牲槽位尾部的视觉间隔
- `param_count >= 5` 守卫：新旧上位机软件混用期间不崩、不读脏数据，倍率格保持空白
