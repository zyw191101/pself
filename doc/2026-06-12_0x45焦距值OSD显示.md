# 新增 0x45 焦距值 OSD 显示功能

**日期：** 2026-06-12
**类型：** 功能开发（上位机协议扩展 + PL 中文 OSD 槽位扩展）

## 问题背景

**需求：** 上位机新增 0x45 命令下发当前传感器焦距值，PS 端需在 OSD 顶部状态栏、惯性状态与方位角之间的位置实时显示该数值。

**协议定义：**

| 字节 | 含义 |
|------|------|
| Byte1 | 命令 ID：0x45 |
| Byte2 | 传感器 ID：0x00-TV，0x01-IR |
| Byte3~4 | 焦距数据，uint16 小端，原始整数显示 |

帧总长 8 字节，无需应答。显示策略：收到哪路传感器的焦距就显示哪路的值，只显示数字本身，不带前缀。

## 原因分析（现状梳理）

动手前先梳理了既有的焦距显示链路，纠正了一个初始误判：

- **初始判断（错误）：** 以为焦距显示挂在 0x21 命令下。实际排查发现 0x21 是 OSD 信息更新命令（按 location_id 分发日期、时间、增强等级、载机/目标经纬高等），里面没有焦距字段。
- **实际情况：** 既有焦距显示走 **0x22 系统信息命令**（`device.cpp` `case 0x22`，show_type 0/1 → "TV FOCUS"/"IR FOCUS"），属于临时提示类显示——只在屏幕下方居中显示 3 秒后自动消失。这与"常驻状态栏显示"的新需求不符，因此需要新命令 + 新 OSD 槽位，而不是复用 0x22。

**相关架构背景：**

1. **UART 帧解析框架**（`HostUARTDevice`）：帧格式为 `0xCC | 0x06(地址) | LEN(总长) | 命令ID | 参数 | CRC`，其中 CRC 为**命令 ID + 参数字节**的 8 位累加和（不含帧头/地址/长度）。`read_byte → read → parse_command → read_command(switch command_id)` 链路已经现成，新增命令只需在 `read_command` 的 switch 中加分支。
2. **中文 OSD 机制**：每个显示区域是一个 `OSD_INFO` 槽位（`osd_idx` 对应 PL BRAM 中的固定条目），内容是 32 元素的 `unsigned short` 数组（ASCII 直接存字符值，汉字存字模索引对），通过 `update_OSD_chinese()` 写入 BRAM。槽位 0~28、30~39 已占用，**29 空闲**，本次启用。
3. **主循环刷新模式**：每个 OSD 项在主循环里用 static 变量缓存上次值，与单例成员比较，变化（或 `show_level` 变化）时才重写 BRAM，避免每帧刷写。

## 解决方案

### 数据流

```
上位机 0x45 帧 ──HostUART RX──► read_command case 0x45
    解析 sensor_id + focus(uint16 LE)
    focus_str = pad_str(format("%d", focus), 5, -1)   ← 固定 5 位左对齐
                          │
main 主循环检测 focus_str 变化 ──► 写入 osd_focus[32] ──► update_OSD_chinese(osd_pos_focus)
                          │
            PL BRAM 槽位 29（ver_y=20, hor_x=800）
```

### 关键设计点

- **固定宽度 pad 而非清空重写**：`pad_str(…, 5, -1)` 把数值固定为 5 字符（uint16 最大 65535 恰好 5 位），数值位数变少时旧数字被空格覆盖，避免残留。这是仿照 yaw_str/pitch_str 的既有做法。
- **位置**：惯性块在 hor_x=610，方位块在 hor_x=990，同在 ver_y=20 一行，新槽位取中间 hor_x=800。
- **显示条件**与相邻的惯性/方位一致：`show_level` 为 1/2/5/6 时显示。
- **不回应答**：协议明确无需 ack，分支里不调用 `write_command_new`。
- `focus_sensor_id` 已解析并保存但暂未参与显示逻辑，为后续按通道区分显示预留。

## 测试方法

用 `gen_focus_frame.py` 生成帧，从 HOST RS422 一路用串口助手 hex 发送：

```bash
python3 gen_focus_frame.py 0 123    # → CC 06 08 45 00 7B 00 C0  (TV, 焦距123)
python3 gen_focus_frame.py 1 456    # → CC 06 08 45 01 C8 01 0F  (IR, 焦距456)
```

边界用例：焦距 0、65535（验证 5 位显示不溢出）。

## 注意事项

- **CRC 范围易错**：累加和只覆盖命令 ID + 参数，不含帧头 0xCC、地址 0x06、长度字节。CRC 错误时帧被**静默丢弃**（仅 `mismatched_crc_cnt` 计数，无日志），排查时可设启动参数 `print_read_byte=1` 确认字节是否到达。
- **程序启动后焦距位置为空**（初始化为空格串），收到第一条 0x45 后才显示数值，属预期行为。
- **OSD 槽位 29 已被占用**，后续新增显示项需另寻索引（30~39 也已占用，需确认 BRAM 容量上限后向 40+ 扩展）。
- 字节序为小端（Byte3 低字节、Byte4 高字节），与本协议其他 uint16 字段一致。
- 显示带中文标签的方案被排除：PL BRAM 字库固定且容量受限（见 `OSD_FONT_SIZE_LIMITATION.md`），"焦距"二字字模不一定存在，且需求方明确只显示数值。

## 复盘（对内）

- **错误判断**：凭印象认为焦距显示在 0x21 下。教训：这类"命令 ID → 功能"的映射不要靠记忆，先 grep 命令号确认 switch 分支再下结论。
- **下次遇到类似问题第一步**：新增上位机命令时，先看 `HostUARTDevice::parse_command`/`struct_command` 确认帧格式和 CRC 规则，再看 `read_command` 找空闲命令号；新增 OSD 项时，先看 `osd_graph_txt_chineseChar_app.cpp` 初始化函数末尾的槽位占用注释。
