# OSD 中文行布局重排

## 问题背景

**现象：** 新增的放大倍率（0x26 Byte5~6）和焦距值（0x45）分别写在行1末尾和行2中部，视觉上"藏"在视角、增强等信息后面，不够突出。

**需求：** 将两者提到最前面，从左起按「传感器类型 → 放大倍率 → 焦距值」排列，其余内容顺延，放不下的移到行2。

**影响：** 两行共 32 个槽位，每个汉字占 2 槽，空间紧张，需要精确规划。

---

## 原因分析

中文 OSD 使用两个 `unsigned short[32]` 数组，分别对应屏幕同一行的左（hor_x=54）和右（hor_x=610）：

- 行1 `osd_sensor_viewangle_enhance_viewstate_bricont_ir`
- 行2 `osd_inertia_velocitycompensation_workmode`

**原布局（行1）：**
```
[0]~[3]   传感器类型
[5]~[10]  视角值（6字符）
[14]~[15] 增强等级
[18]~[22] 放大倍率（5字符）← 靠后
[24]~[27] 手动/自动
[28]~[31] 红外极性
```

放大倍率在 [18]，焦距在行2 [22]，都不在视线第一落点。

**容量核算：**

新顺序的前三项（传感器4 + 空1 + 放大倍率5 + 空1 + 焦距5 = 16槽）用掉一半。
剩余 16 槽放视角(6) + 增强(2) + 手动自动(4) = 12 槽，含空隙后刚好能塞下（[16]~[30]），红外极性（4槽）塞不进，顺延行2。

---

## 解决方案

### 新布局

**行1：**
```
[0]~[3]   传感器类型
[5]~[9]   放大倍率（"xx.xX"）
[10]      ' '
[11]~[15] 焦距值
[17]~[22] 视角值
[24]~[25] 增强等级
[27]~[30] 手动/自动
```

**行2（原有不动，末尾追加）：**
```
[14]~[21] 工作模式（不变）
[22]~[25] 红外极性（从行1顺延）
```

| 改动 | 文件位置 | 说明 |

| 视角写入 `[i+5]` → `[i+17]` | main.cpp ~4807 | |
| 增强等级 `[14/15]` → `[24/25]` | main.cpp ~4818 | 用 sed 按行范围替换 |

## 踩坑：sed 连锁替换

### 现象

用一条 sed 命令连续替换手动/自动的四个索引：
```bash
sed -i '...s/[24]/[27]/g; ...s/[25]/[28]/g; ...s/[26]/[29]/g; ...s/[27]/[30]/g'
```

执行后发现 `CH_idx_shou_848_1` 跑到了 `[30]` 而不是预期的 `[27]`。

### 根本原因

sed 的多个替换表达式**在同一行上顺序执行**。第一条 `[24]→[27]` 把 `shou_848_1` 放到 `[27]`，第四条 `[27]→[30]` 随后又把它改成了 `[30]`。原本在 `[27]` 的 `dong_327_2` 也正确地变成了 `[30]`，所以错误不明显——两行都是 `[30]`，看起来像"重复写"。

### 排查过程

对比改后输出和预期：发现 `shou_848` 和 `zi_1220` 在错误的位置（[30] 而非 [27]），其余三项正确。定位到这两个是"被中途二次替换"的受害者。

### 修复

替换完成后，针对这两行做定向修正：
```bash
sed -i '4898s/[30] = CH_idx_shou_848_1/[27] = CH_idx_shou_848_1/;
        4906s/[30] = CH_idx_zi_1220_1/[27] = CH_idx_zi_1220_1/' main.cpp
```

### 下次遇到类似问题，第一步应该看什么

多步 sed 替换后，验证**每一项**的新旧值是否符合预期，而不是只看"有没有报错"。遇到奇怪重复或错位，优先怀疑连锁替换。

**更安全的替换方法：**
- 反向替换（先改大索引，后改小索引），避免"刚改完的值被后续步骤再次命中"
- 或者使用有行号精度的工具（如 Edit 工具逐行改），代替 sed 全局替换
