# GitHub 远程仓库接入与跨平台换行符问题处理

**日期：** 2026-06-12
**类型：** 工程基础设施（Git 多端协作 + 跨平台换行符治理）

## 问题背景

项目此前只有一个内网 GitLab 远程，开发分布在两个环境：

- **Docker 容器**（Linux，`/workspace/PSElf`）：Claude Code 辅助开发
- **Windows 端**（`D:\vzwuProject\...\src`，MINGW64）：本地编辑

两端各自是独立的 clone，没有公共远程做同步。本次接入 GitHub 仓库 `github.com/zyw191101/pself` 作为两端同步的中转，过程中暴露并处理了两个典型问题：**HTTPS 推送无凭据**和**CRLF/LF 换行符污染工作区**。

## 操作过程与问题处理

### 1. 添加远程与推送（容器端）

```bash
git remote add github https://github.com/zyw191101/pself
git push -u github 20260316
# → fatal: could not read Username for 'https://github.com'
```

容器内无交互终端、无 gh CLI，HTTPS 方式拿不到凭据。检查发现 `~/.ssh/` 下已有 `github_key` 且 `~/.ssh/config` 配置好了 `Host github.com`，改用 SSH 地址即推送成功：

```bash
git remote set-url github git@github.com:zyw191101/pself.git
git push -u github 20260316
```

> 结论：容器环境推 GitHub 优先用 SSH；HTTPS 需要 credential helper 或 PAT，交互受限时不可行。

### 2. 提交范围控制

提交前 `git status` 显示 13 个文件被修改、5 个未跟踪，远多于本次开发实际触碰的范围。**没有直接 `git add -A`**，而是先逐一甄别：

- 用 `git diff --stat` 与 `git diff -w --stat`（忽略空白）对比，发现 8 个文件（.gitignore、video_app.*、osd_graph_txt_app.* 等）`-w` 下 diff 为空，且插入数 == 删除数 → **纯换行符变化，无内容改动**
- 真实改动只有 0x45 功能相关的 5 个源文件 + 2 个新文件

最终只提交了功能相关文件；8 个换行符"改动"用 `git restore` 恢复；`.project`（IDE 文件）、`CLAUDE.md`、`OSD_FONT_SIZE_LIMITATION.md` 按决策保持未跟踪。

### 3. 换行符问题的根因

本质是**跨平台换行符不一致**问题：仓库 blob 统一是 LF，但项目曾经过 Windows 共享目录中转，部分工作区文件被 Windows 端工具（编辑器/同步）改写成 CRLF。后果：

- `git diff` 显示整文件被改（上千行），淹没真实改动
- 若不甄别直接提交，会产生巨大的噪音 diff，破坏 blame 和后续 review

**甄别手法（重要）：**

```bash
git diff -w --stat          # 忽略空白后为空 → 纯换行符/空白变化
git diff <file> | grep "^+" | head | cat -A   # 看 ^M$ 确认 CRLF 方向
```

本次对被 0x45 功能触碰的两个 OSD 文件用 `sed -i 's/\r$//'` 归一为 LF 后再提交（保证 diff 只含真实改动）；未触碰的 8 个文件直接 `git restore`。

### 4. 两端历史分叉与合并

推送后发现 Windows 端比容器端多一个提交（`1baa23d 注释掉调试打印串口信息代码`），两端在 `972784a` 后分叉：

```
                    ┌── 1baa23d 注释调试打印（Windows 独有）
... ── 972784a ─────┤
                    └── f8cf70f 0x45焦距值（容器 → GitHub）
```

同步流程：

1. Windows 端 `git remote add github https://...`（Windows 有凭据管理器，HTTPS 可用）+ `git fetch github`
2. 首次 merge 被工作区未提交的 main.cpp 改动挡住 → 用 `git diff -w --stat` 甄别后处理（同样是换行符问题，`git restore` 解决）
3. `git merge github/20260316` 自动合并成功（两边改动区域不同，无冲突），生成合并提交 `fca3739`
4. Windows 端 `git push github 20260316`
5. 容器端 `git pull github 20260316`，快进到 `fca3739`，两端一致

## 关键命令速查

| 场景 | 命令 |
|------|------|
| 甄别换行符假改动 | `git diff -w --stat`（为空即纯空白变化） |
| 确认 CRLF 方向 | `git diff <file> \| grep "^+" \| head \| cat -A`（看 `^M$`） |
| 丢弃换行符污染 | `git restore <files>` |
| 文件归一为 LF | `sed -i 's/\r$//' <files>` |
| dubious ownership | `git config --global --add safe.directory <路径>` |

## 后续协作流程

```
容器开发 → push github → Windows pull
Windows 开发 → push github → 容器 pull
```

## 注意事项

- **每次合并/提交前先跑 `git diff -w --stat`**，确认有多少是真实改动。只要文件再被 Windows 端工具碰过，CRLF 污染就会复发。
- 根治方案是加 `.gitattributes`（如 `* text=auto eol=lf`）统一换行符策略，本次未做，复发频繁时再上。
- 容器端 push 用 SSH（`git@github.com:`），Windows 端用 HTTPS（走凭据管理器），两端配置不同是正常的。
- 提交范围宁可手动列文件，不用 `git add -A`——本次如果全量提交，会把 5000+ 行换行符噪音和 IDE 文件一起带进仓库。

## 复盘（对内）

- **下次遇到"莫名其妙一堆文件被改"，第一步**：`git diff -w --stat`。空白/换行符问题在跨 Windows 的项目里是常态，不要急着 stash 或提交。
- merge 被 "local changes would be overwritten" 挡住时，先甄别改动性质再选 restore/commit，**不要随手 stash**——stash pop 可能和合并结果二次冲突，处理更绕。
