# 0x45 焦距值 OSD 遮挡问题与槽位复用改造

**日期：** 2026-06-12
**类型：** 方案纠错（OSD 硬件渲染机制理解 + 显示布局改造）
**前置记录：** [2026-06-12_0x45焦距值OSD显示.md](./2026-06-12_0x45焦距值OSD显示.md)（原方案，本文将其废弃）

## 问题背景

**现象：** 原方案为焦距值新增独立 OSD 槽位 29（`hor_x=800, ver_y=20, Enable=1`），板上实测发现该槽位启用后，其右侧同一行的其他 OSD 内容（方位角等）被一片"空白"盖住。

**触发条件：** 槽位 29 只要 Enable=1 就复现，即使 `str_arr` 是全 0 的 `osd_blank`、`valid_length=0`。

**影响：** 同一行 hor_x=800 以右约 512 px 范围内的显示内容被遮挡，焦距功能无法上线。

## 原因分析

本质上是对 **PL 硬件字符生成器渲染粒度**的理解偏差，叠加一个**未使用字段造成的误导**。

背景机制（结合 `update_OSD_chinese()` 实现与板上实测确认）：

1. PS 侧 `update_OSD_chinese()` 对每个槽位**无条件写入全部 32 个字符索引**到 BRAM，不参考 `valid_length`（`osd_graph_txt_chineseChar_app.cpp:567` 的 for 循环固定跑满 `MAX_OSD_STRING_LENGTH_IN_CHINESE`）。
2. PL 侧对启用的槽位**固定渲染 32 个字符格**（每格 16×32 px），`OSD_INFO.valid_length` 字段 PL 并不使用（与 `OSD_FONT_SIZE_LIMITATION.md` 的记载一致）。
3. 字符索引 0 对应的字模在 PL 中是**不透明空白格**，不是透明。

三条叠加的结果：一个"空"槽位（osd_blank）启用后，等于在屏上铺了 32 格 × 16 px = 512 px 宽的不透明空白条。原方案把它放在 hor_x=800 的信息密集行（ver_y=20），必然盖住右侧内容。

> 错误判断复盘：开发时默认"索引 0 = 不显示"，且以为 `valid_length` 能限制渲染长度。两个假设都没有在硬件上验证就写了代码。

## 解决方案

### 方案选择

排除过的方向：

- **用 `valid_length` 限制为 5 格** — PL 不使用该字段，软件侧改了没用；
- **寻找 PL 中透明的字符索引** — 需逐个试字模，且即使找到，独立槽位仍占用一行中 32 格的连续区域，布局上不经济。

最终方案（用户提出）：**不新增槽位，复用现有槽位 7（惯性/速度补偿/工作模式行，`hor_x=610, ver_y=20`）的空闲字符格**。依据：检查 `main.cpp` 全部运行时分支，该槽位数组只有 `[0]~[21]` 被写过，`[22]~[31]` 自静态初始化后永远是 0——这些格子本来就在屏上渲染着，现状已被接受，往里面填焦距字符不会引入任何新的遮挡。

### 实现

- `main.cpp` 0x45 分支：焦距字符串写入 `osd_inertia_velocitycompensation_workmode[23]~[27]`（5 格预留，`[22]` 留空与工作模式文字分隔），新值不足 5 字符时多余格补 0 还原；不再操作 Enable，**显隐跟随槽位 7 的工作模式逻辑**（show_level 1/2/5/6）。
- 删除 `osd_pos_focus`、`osd_focus[32]` 的声明、定义和初始化。
- 槽位 29 改为备用槽 `osd_pos_29`，初始化**显式写 Enable=0**（坐标照抄相邻备用槽 30/31 的模式，反正不渲染）。

### 关键坑：BRAM 幽灵槽位

槽位 29 的处理不能是"直接删掉相关代码"。OSD 配置存放在 PL BRAM（`0x40000000`）中，**程序退出/重启不会清零，只有掉电才会**。旧版本二进制已经把槽 29 的 Enable 位写成 1，如果新程序对槽 29 不做任何写入，热重启后旧配置仍然生效——遮挡照旧，且现象会让人误以为新方案没生效。所以必须保留一次显式的 `Enable=0` 写入。

> 这是典型的**外部持久状态**问题：代码删干净 ≠ 硬件状态删干净。同类场景（VDMA 配置、Mixer 层使能）同理。

## 注意事项

- **几何重叠风险（待实测）**：格 [23] 的屏幕 x = 610 + 23×16 = 978，格 [24] 起 ≥ 994，与同行 yaw 槽位（`hor_x=990`）区域重叠。焦距值实际较短，5 格只是预留；若实测压到 yaw，调整起始索引或 yaw 位置。
- **显隐与工作模式绑定**：一个槽位只有一个 Enable 位。0x45 不单独控制显隐；若以后需要单独隐藏焦距值，只能往 [23]~[27] 写空白，不能动 Enable，否则工作模式文字陪葬。
- **`str_arr` 不能不赋值**：`update_OSD_chinese()` 无条件读 32 个元素，野指针会把垃圾写进 BRAM 或段错误。所有槽位初始化必须指向一个 ≥32 元素的有效数组（`osd_blank` 只是惯用值，不是唯一选择）。
- 槽位 7 数组的 `[22]~[31]` 从此被焦距功能占用 [23]~[27]，后续若有人想用该区段需先查本记录。

## 复盘（对内）

- **下次给 OSD 加新显示项，第一步不是找空槽位，而是看同行现有槽位数组的空闲索引段**——PL 按槽位整 32 格渲染的前提下，复用比新增便宜且无遮挡风险。
- 涉及 PL 硬件行为的假设（"0 是透明的"、"valid_length 有效"），写代码前先用最小实验在板上验证，成本远低于返工。
- 删除"曾经写过硬件寄存器/BRAM 的功能"时，检查是否需要补一次显式的清除写入。
